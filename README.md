# 체리 준비노트

광배·민주 둘만 쓰는 출산 준비 웹앱입니다. Vite + React + TypeScript로 만들었고, 데이터와 로그인은 Firebase(무료 Spark 요금제), 배포는 Vercel, 2시간 후 혈당 푸시는 Vercel 함수 + cron-job.org를 씁니다.

- **용품 준비**: 엑셀 체크리스트 106개가 처음 로그인할 때 자동으로 들어가요.
- **정보 노트**
- **신청·서류**: 22개가 처음 로그인할 때 자동으로 들어가요.
- **혈당 일지**: 월 달력, 공복과 세 끼 기록, 식사 사진, 식후 2시간 푸시
- **공통**: 전체 검색, ★중요(홈에 표시), 목록에서 상태 바로 바꾸기, 엑셀/JSON 백업

> Spark 요금제는 결제 수단이 등록되어 있지 않아서 **요금이 나올 수 없어요.** 한도를 넘으면 그날만 막히는데, 두 사람 사용량은 한도의 1%도 안 돼요.

---

## 0. 준비물
- 구글 계정 (Firebase), GitHub 계정, Vercel 계정 (GitHub로 가입)
- 두 사람이 로그인할 이메일 주소 2개 (실제 메일함일 필요는 없지만 본인 이메일을 권장)
- PC에 Node.js 18 이상

## 1. Firebase 프로젝트 만들기 (약 15분)

### 1-1. 프로젝트 생성
1. https://console.firebase.google.com 에서 **프로젝트 추가** → 이름 `cherry-note` (아무거나)
2. Google 애널리틱스는 **사용 안 함** → 만들기
3. 요금제는 기본값인 **Spark(무료)** 그대로 둡니다.

### 1-2. 웹 앱 등록 → 설정값 얻기
1. 프로젝트 개요 옆 톱니바퀴 → **프로젝트 설정** → 아래쪽 **내 앱** → `</>`(웹) 아이콘
2. 앱 닉네임 `cherry-web`, Hosting 체크는 **하지 않음** → 앱 등록
3. 화면에 나오는 `firebaseConfig`의 값 6개를 메모해 둡니다.
   - `apiKey` → `VITE_FIREBASE_API_KEY`
   - `authDomain` → `VITE_FIREBASE_AUTH_DOMAIN`
   - `projectId` → `VITE_FIREBASE_PROJECT_ID`
   - `storageBucket` → `VITE_FIREBASE_STORAGE_BUCKET`
   - `messagingSenderId` → `VITE_FIREBASE_MESSAGING_SENDER_ID`
   - `appId` → `VITE_FIREBASE_APP_ID`

> 이 값들은 공개되어도 괜찮게 설계된 값이에요. 실제 보호는 3단계의 **보안 규칙**이 합니다.

### 1-3. 로그인(Authentication)
1. 왼쪽 메뉴 **빌드 → Authentication → 시작하기**
2. **로그인 방법** 탭 → **이메일/비밀번호** → 사용 설정 → 저장 (이메일 링크는 끄기)
3. **사용자** 탭 → **사용자 추가**로 두 사람 계정을 만듭니다 (이메일 + 비밀번호).
4. (권장, 메뉴가 보이면) **설정** 탭 → **사용자 작업** → "만들기(가입) 사용 설정"을 **끄기**. 다른 사람이 가입 자체를 할 수 없게 돼요. 이 메뉴가 없어도 보안 규칙 때문에 데이터에는 접근할 수 없어요.

### 1-4. 데이터베이스(Firestore)
1. **빌드 → Firestore Database → 데이터베이스 만들기**
2. 위치: `asia-northeast3 (서울)` 추천 → **프로덕션 모드**로 시작
3. **규칙** 탭을 열고 이 저장소의 `firestore.rules` 내용을 붙여넣습니다.
   **두 이메일 주소를 실제 주소로 바꾼 뒤** → **게시**

```
request.auth.token.email in ['광배이메일@gmail.com', '민주이메일@gmail.com']
```

> 이 규칙 때문에 앱 주소를 누가 알아도, 두 계정이 아니면 데이터를 한 줄도 읽거나 쓸 수 없어요.

### 1-5. 푸시 알림 키(VAPID)
1. **프로젝트 설정 → 클라우드 메시징** 탭
2. 맨 아래 **웹 구성 → 웹 푸시 인증서 → 키 쌍 생성**
3. 생성된 키를 `VITE_FIREBASE_VAPID_KEY`에 씁니다.
   - 위쪽의 "Firebase Cloud Messaging API (V1)"이 **사용 설정됨**인지도 확인하세요.

### 1-6. 서비스 계정 키 (Vercel 함수가 푸시를 보낼 때 사용)
1. **프로젝트 설정 → 서비스 계정** 탭 → **새 비공개 키 생성** → JSON 파일 다운로드
2. 이 파일은 **절대 GitHub에 올리지 마세요.** (`.gitignore`에 막아둠)
3. 한 줄짜리 base64로 바꿉니다.
   - Mac: `base64 -i 받은파일.json | tr -d '\n' | pbcopy` (클립보드로 복사됨)
   - Windows PowerShell: `[Convert]::ToBase64String([IO.File]::ReadAllBytes("받은파일.json")) | Set-Clipboard`
4. 복사된 값을 `FIREBASE_SERVICE_ACCOUNT_B64`에 씁니다.

## 2. 내 PC에서 실행해보기 (선택, 5분)

```bash
npm install
cp .env.example .env.local   # 위에서 메모한 VITE_ 값들 채우기
npm run dev                  # http://localhost:5173
```

`VITE_USER_NAMES`에는 `광배이메일:광배,민주이메일:민주` 형식으로 넣으세요. 앱에 표시되는 이름이에요.

> 로컬에서는 `/api/cron-push`(푸시 발송 함수)가 돌지 않아요. 푸시는 Vercel에 올린 뒤에 테스트합니다.

## 3. GitHub → Vercel 배포 (10분)

1. GitHub에 **Private** 저장소를 하나 만들고 이 폴더를 올립니다.
   ```bash
   git init && git add . && git commit -m "체리 준비노트"
   git branch -M main
   git remote add origin https://github.com/<아이디>/cherry-note.git
   git push -u origin main
   ```
2. https://vercel.com → **Add New → Project** → 방금 만든 저장소 **Import**
3. Framework Preset은 **Vite**로 자동 인식됩니다. 빌드 설정은 그대로 둡니다.
4. **Environment Variables**에 아래 10개를 넣습니다.

| 이름 | 값 |
|---|---|
| `VITE_FIREBASE_API_KEY` 외 `VITE_FIREBASE_*` 6개 | 1-2에서 메모한 값 |
| `VITE_FIREBASE_VAPID_KEY` | 1-5 |
| `VITE_USER_NAMES` | `광배이메일:광배,민주이메일:민주` |
| `FIREBASE_SERVICE_ACCOUNT_B64` | 1-6 |
| `CRON_SECRET` | 아무 긴 랜덤 문자열 (예: 비밀번호 생성기로 32자) |

5. **Deploy** → 끝나면 `https://cherry-note-xxxx.vercel.app` 같은 주소가 생깁니다.
6. (선택) Vercel 프로젝트 설정 → **Deployment Protection**은 꺼진 상태(기본)여야 cron이 함수를 호출할 수 있어요.

> 환경변수를 나중에 바꾸면 **Redeploy**를 한 번 해야 적용돼요. `VITE_` 값은 빌드할 때 앱에 들어가기 때문이에요.

## 4. 2시간 후 푸시: cron-job.org 연결 (5분)

Vercel 무료 요금제의 크론은 하루 1번만 돌아서, 1분마다 깨워줄 무료 크론 서비스를 씁니다.

1. https://cron-job.org 가입 → **CREATE CRONJOB**
2. URL: `https://<내-vercel-주소>/api/cron-push?key=<CRON_SECRET 값>`
3. Execution schedule: **Every minute**
4. 저장 → **TEST RUN** → 응답이 `{"ok":true,"sent":0}`이면 성공이에요.
   - `401`이 나오면 `CRON_SECRET`이 맞지 않는 거예요.
   - `500`이 나오면 서비스 계정 값(base64)을 다시 확인하세요.

동작 방식은 이래요.
- 앱에서 식사 사진을 찍으면 Firestore `alarms`에 "몇 시에 보낼지"가 저장돼요.
- 이 함수가 1분마다 확인해서 시간이 된 알람을 두 사람 폰으로 보내고 지워요.
- 수치를 먼저 입력하면 알람은 자동으로 취소돼요.

## 5. 폰에 설치하기

### 아이폰 (iOS 16.4 이상)
1. **사파리**로 Vercel 주소 열기 (크롬 앱 말고 사파리)
2. 공유 버튼 → **홈 화면에 추가** → 추가
3. 홈 화면의 **체리노트 아이콘으로 열기** → 로그인 (이후 유지됨)
4. **혈당** 탭 → **알림 켜기** → 허용
   - 아이폰은 홈 화면에 추가한 앱에서만 푸시를 받을 수 있어요. 사파리 탭에서는 버튼이 안내 문구로 바뀌어요.
5. **설정** 화면 → 혈당 알림 **테스트** → 알림이 뜨면 완료

### 안드로이드
1. **크롬**으로 주소 열기 → 메뉴(⋮) → **앱 설치** 또는 **홈 화면에 추가**
2. 앱으로 열어서 로그인 → 혈당 탭 **알림 켜기**

> 알림은 **폰마다 각각** 켜야 해요. 두 사람 다 켜두면 알람이 두 폰에 같이 울려요.

### 실제 알람 테스트
1. 혈당 탭에서 오늘 저녁 칸을 눌러 아무 사진이나 찍습니다.
2. 그 칸을 다시 눌러 **측정 시간**을 지금부터 2분 뒤로 바꾸고 저장합니다.
3. 앱을 닫고 기다립니다. 1~2분 안에 푸시가 오면 성공이에요.

## 6. 쓰는 법 요약

- **혈당**
  - 공복 칸 누르기 → 키패드로 숫자 → 확인 (자동 저장)
  - 아침·점심·저녁 칸 누르기 → 바로 카메라 → 찍으면 자동 저장 + 2시간 후 알람
  - 알람이 오면 그 칸의 **입력** → 숫자 → 확인
  - 사진 찍은 직후 뜨는 안내에서 **사진첩 저장**을 누르면 원본이 사진첩에 남아요. 아이폰 웹은 사진첩에 자동 저장이 안 돼서, 공유 시트의 '이미지 저장'을 한 번 눌러줘야 해요.
  - 달력에서 목표를 넘은 횟수만큼 날짜 색이 진해져요. 기준은 설정에서 바꿀 수 있어요.
- **빠른 상태 변경**
  - 용품·신청은 상태 칩을 누르면 바로 바뀌어요.
  - 신청은 왼쪽 동그라미를 누르면 바로 완료돼요.
  - 바꾼 직후 뜨는 안내에서 **되돌리기**를 누르면 원래대로 돌아가요.
- **★중요**: 어느 메뉴든 별을 누르면 홈에 모여요. 홈에 보일 개수는 설정에서 바꿀 수 있어요.
- **검색**: 제목, 카테고리, 금액, 구매처, 메모, 태그, 상태 이름까지 전부 대상이에요. 띄어쓰기로 여러 단어를 넣으면 모두 포함된 것만 찾아요.

## 7. 백업과 데이터

- 데이터는 내 Firebase 프로젝트의 Firestore에 있어요. 프로젝트를 직접 지우지 않는 한 그대로 남아요.
- **설정 → 엑셀로 받기**: 4개 메뉴가 시트별로 정리된 엑셀 파일이에요. 앱이 없어도 열어볼 수 있어요.
- **설정 → 전체 백업(JSON)**: 사진까지 포함한 원본이에요.
- 마지막 백업 후 2주가 지나면 홈에 알림이 떠요.
- 오프라인 캐시가 켜져 있어요. 잠깐 인터넷이 끊겨도 입력은 폰에 저장됐다가, 연결되면 자동으로 올라가요.

### 데이터 구조 (Firestore)
| 컬렉션 | 내용 |
|---|---|
| `items` | 용품 준비 |
| `notes` | 정보 노트 |
| `admin` | 신청·서류 |
| `sugar` | 혈당 기록. 문서 id는 `YYYY-MM-DD_slot` |
| `photos` | 압축한 사진 (dataURL, 장당 약 0.4MB 이하) |
| `alarms` | 보낼 푸시 예약 |
| `tokens` | 폰별 푸시 토큰 |
| `meta/settings` | 예정일, 목표 수치, 홈 중요 개수, 마지막 백업 |
| `meta/lists` | 용품 카테고리, 노트 태그 목록 |
| `meta/seed` | 초기 데이터를 넣었다는 표시 |

엑셀 초기 데이터를 다시 넣고 싶으면, `items`와 `admin`을 비운 뒤 `meta/seed` 문서를 지우고 앱을 새로고침하세요.

## 8. 문제 해결

| 증상 | 해결 |
|---|---|
| 로그인 후 "접근 권한이 없어요" | `firestore.rules`의 이메일이 로그인 이메일과 정확히 같은지 확인 (대소문자 포함) |
| 앱이 빈 화면 | Vercel 환경변수의 `VITE_FIREBASE_*` 확인 후 Redeploy |
| 알림 켜기를 눌러도 반응 없음 (아이폰) | 사파리 탭이 아니라 홈 화면 아이콘으로 열었는지, iOS 16.4 이상인지 확인 |
| 푸시가 안 옴 | cron-job.org 실행 기록이 200인지 → Firestore `tokens`에 두 폰이 있는지 → `alarms`의 `fireAt`이 지났는지 |
| 사진 저장 실패 | 사진이 너무 크면 자동으로 줄이는데, 그래도 실패하면 다른 사진으로 시도 |
